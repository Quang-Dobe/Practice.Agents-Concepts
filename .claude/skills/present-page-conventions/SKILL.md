# Present Page Conventions

Every topic folder gets a `present/` folder: four dark-themed HTML pages that re-author the topic's `docs/` into an easy-to-skim, diagram-first web experience. This skill is the **single source of truth** so every topic looks and reads identically. When in doubt, match the templates and the golden reference rather than improvise.

You do **not** write CSS or JS. Everything is in the shared, already-built, committed files:
- `/assets/site.css` — the complete stylesheet (all component classes below).
- `/assets/site.js` — theme toggle, mermaid, sidebar, active-nav, progress bar, dashboard search.
- `/assets/vendor/mermaid.min.js` — vendored, offline. **No CDNs anywhere, ever. No web fonts.**
- `/assets/favicon.svg` — shared favicon.

**Start from the four annotated templates** in this skill's folder:
`.claude/skills/present-page-conventions/templates/{index,overview,detail,practice}.html`.
Copy the one you need into the topic's `present/` folder, fill it in, and delete the `<!-- IMPLEMENTER: … -->` notes.

**Living golden reference** — copy its structure, depth, and quality precisely:
`backend/circuit-breaker/present/{index,overview,detail,practice}.html`.

## 1. Where files go, and the path rule

Every topic gets a `present/` folder with exactly four pages:

```
<category>/<topic-slug>/present/
├── index.html      ← topic landing (hero + map + hero diagram)
├── overview.html   ← re-authored from docs/01-overview.md
├── detail.html     ← re-authored from docs/02-deep-dive.md
└── practice.html   ← re-authored from docs/03-practice.md
```

**The path rule is absolute.** Every present page sits *exactly 3 directory levels deep*
(`<category>/<topic>/present/`), so shared assets are **always**:

```html
<link rel="icon" type="image/svg+xml" href="../../../assets/favicon.svg">
<link rel="stylesheet" href="../../../assets/site.css">
<script src="../../../assets/vendor/mermaid.min.js"></script>
<script src="../../../assets/site.js"></script>
```

Other fixed links from a present page:
- View code:      the topic's `code/` folder **on GitHub** — `https://github.com/Quang-Dobe/Practice.Agents-Concepts/tree/main/<category>/<topic>/code`, opened with `target="_blank" rel="noopener"`. (A relative `../code/` link 404s on GitHub Pages, which does not auto-index directories.)
- All topics:     `../../../index.html`  (root dashboard)
- Sibling pages:  `index.html`, `overview.html`, `detail.html`, `practice.html` (bare filenames)

The **root dashboard** (`/index.html`) is generated by `scripts/gen-dashboard.mjs`, not hand-written — see §7.

## 2. Design tokens (already in `:root`, do not redefine)

| Token | Value | Use |
|---|---|---|
| `--bg` | `#0d1117` | page background |
| `--bg-elev` | `#161b22` | cards, sidebar, callouts |
| `--bg-elev-2` | `#1c2129` | diagrams, code, deep tiles |
| `--border` / `--border-soft` | `#30363d` / `#21262d` | borders |
| `--text` / `--text-muted` / `--text-faint` | `#e6edf3` / `#8b949e` / `#6e7681` | text ramp |
| `--success` / `--warn` / `--danger` / `--info` | `#3fb950` / `#d29922` / `#f85149` / `#58a6ff` | status |
| `--accent` / `--accent-soft` | per category (below) | the topic's color |

### Category accents — set the body class, nothing else

Put **one** class on `<body>` (plus `data-category`). `--accent`/`--accent-soft` flow into every component automatically.

| Category | body class | accent |
|---|---|---|
| ai | `cat-ai` | `#a371f7` |
| backend | `cat-backend` | `#3fb950` |
| frontend | `cat-frontend` | `#58a6ff` |
| database | `cat-database` | `#d29922` |
| cloud | `cat-cloud` | `#ec6547` |
| general-concept | `cat-general-concept` | `#ec6cb9` |

```html
<body class="cat-database" data-category="database">
```

A **light-mode** toggle ships wired in the sidebar (persisted, default dark); don't add per-page theme code. **Dark is the priority target** — always verify your page in dark first.

## 3. The shared shell (identical on all four topic pages)

Copy verbatim from any template; only the topic name/category change:

1. `<a class="skip-link">` + `<div class="progress-bar">` right after `<body>`.
2. `<header class="topbar">` (mobile hamburger + topic title) + `<div class="scrim">`.
3. `<aside class="sidebar" id="sidebar">`, top to bottom:
   - `.sidebar__header`: `<h1 class="sidebar__title">` topic name + `<span class="pill pill--category">` category.
   - `.sidebar__nav`: four `.sidebar__link`s — Home / Overview / Detail / Practice. **Do not add
     `is-active` yourself** — `site.js` sets it from the current filename.
   - `.sidebar__divider` + `.sidebar__code-link` (the GitHub code URL, §1).
   - `.sidebar__spacer` then `.sidebar__foot`: the `.theme-toggle` button and the `.sidebar__back`
     "← All topics" button (`../../../index.html`).
4. `<main class="main" id="main"><div class="content"> … </div></main>`.
5. Scripts before `</body>`: mermaid **first**, then site.js. Neither uses `defer`.

**Every page starts** its `.content` with a `.breadcrumb`: `All topics / <Topic> / <Section>`.

## 4. Per-page blueprint — source section → present block → component

Content is **re-authored, not converted 1:1**: simpler words, dense paragraphs exploded into bullet
**lists**, jargon glossed, key facts/numbers/trade-offs **all preserved**.

### 4a. `index.html` — topic landing
| Block | Component | Notes |
|---|---|---|
| Hero | `.hero` (`.hero__eyebrow` pill+badges, `.hero__title`, `.hero__tagline`) | Tagline = the "30-second" hook, one plain sentence. |
| Key numbers | `.stat-grid` of `.stat` tiles | 3–4 real numbers from the docs. No invented stats. |
| **Hero diagram (REQUIRED)** | `.diagram` with Mermaid **or** inline SVG | The mental model in one picture. |
| "What you'll find" | `.card-grid` of 3 linked `.card`s | Link to overview/detail/practice. |
| Footer nav | `.next-nav` | Back = All topics; Next = Overview. |

### 4b. `overview.html` — from `01-overview.md`
| Source section | Present block | Component |
|---|---|---|
| 30-second version | lead + restatement | `.lead` + `.callout--info` |
| mental model | picture + short prose | `.diagram` (Mermaid or SVG) — **≥1 diagram required** |
| what it is NOT | bulleted mix-ups | `.callout--warn` + `<ul>` |
| when to reach for it | left column | `.do-dont__col--do` |
| when NOT to | right column | `.do-dont__col--avoid` |
| key vocabulary | term/definition | `.vocab` `<dl>` |
| what's next | footer nav | `.next-nav` → Detail |

### 4c. `detail.html` — from `02-deep-dive.md`
| Source section | Present block | Component |
|---|---|---|
| What | precise line → bullets; parts list | `<ul>` + `.vocab` |
| Where | layers/places | `.card-grid` or bullets |
| When | use / don't-use | `.do-dont` or bullets + `.callout--tip` |
| How | request lifecycle | `.steps` **+ a Mermaid** flow/state/sequence |
| **Key trade-offs TABLE** | reproduce **every row** | `.tradeoff` inside `.table-scroll` |
| Common failure modes | one block per mode | stacked `.callout--danger` / `.callout--warn` |
| Why | reasoning + concept picture | prose + optional **inline SVG** |

### 4d. `practice.html` — from `03-practice.md`
| Source section | Present block | Component |
|---|---|---|
| where you'll meet it | contexts | short prose + `.card-grid` |
| Best practices (numbered) | one card per practice | `.practice-card` with Do/Why/Avoid rows — **keep the triad** |
| Anti-patterns | one block per trap | stacked `.callout--danger` (or a `.do-dont`) |
| Real-world usage patterns | mini case studies | `.card-grid` (keep the numbers) |
| Operational checklist | checkable items | `.callout--success` + `<ul>` |
| How it evolves | migration path | `.steps` |
| Further reading | link list | `<ul>` of `<a>` (real external URLs allowed here) |
| — | footer nav | `.next-nav` → View code (the GitHub code URL) |

## 5. Content-transformation rules

1. **Paragraph → bullets.** Any doc paragraph that lists ≥3 things becomes a `<ul>`.
2. **Plain words.** Prefer the shortest true word.
3. **Keep every number, ratio, default, date, and the entire trade-off table.** Shorten *words*, never *facts*.
4. **Gloss jargon on first appearance** with `.term` (both patterns are in `site.css`):
   - **Inline gloss** (preferred, always visible): `<span class="term">chunking</span> <span class="term__gloss">splitting text into small pieces</span>`
   - **Hover tooltip** (for incidental jargon): `<span class="term" data-gloss="approximate nearest-neighbor search">ANN</span>`
   Use inline for the 3–6 load-bearing terms per page; never gloss the same term twice on one page.
5. **One diagram minimum per content page**, plus the hero diagram on `index.html`. See §6.
6. **Preserve tables as tables** (`.tradeoff` + `.table-scroll`). Never flatten a table into prose.
7. **No banned marketing words:** `robust`, `seamless`, `leverage`, `powerful`, `cutting-edge`, `harness`, `unlock`, `delve`, `journey`, `embark`, `navigate the landscape`. (`harness`/`Harness` is allowed only as a proper noun — the topic name or the CD product.)

## 6. Diagram catalog — what to draw and with what

**Mermaid** (`<pre class="mermaid">`) for flows, state machines, sequences, graphs, ER — boxes-and-arrows.
**Inline SVG** (hand-authored, no JS) for bespoke *spatial / geometric* ideas Mermaid can't express (layouts, memory/pool pictures, number lines, coordinate spaces, packet framing). Wrap every diagram in `<figure class="diagram"> … <figcaption class="diagram__caption">`.

The topic's docs already contain ASCII diagrams — **convert those into real Mermaid/SVG**.

| Page / section | Suggested diagram | Mermaid or SVG |
|---|---|---|
| `index` hero | the mental model in one shape | Mermaid **or** SVG metaphor |
| `overview` mental model | the everyday loop / core analogy | Mermaid flow; SVG if spatial |
| `detail` How | request/data lifecycle | **Mermaid** `sequenceDiagram` / `stateDiagram-v2` |
| `detail` Where | layer stack | Mermaid `flowchart TB` subgraphs, or a small SVG stack |
| `detail` Why | the failure it prevents | **inline SVG** |
| `practice` comparison | option A vs B | Mermaid subgraphs, or a `.tradeoff` table |

Mermaid notes:
- `site.js` initializes and runs mermaid and re-themes on toggle. **You only write the `<pre class="mermaid">` source.** Do not call mermaid yourself.
- **Never put a literal `<br/>` inside a mermaid block** — the browser parses it and corrupts the source. Use single-line labels or `\n`.
- If a diagram fails to parse the raw source stays visible and the page still works — but eyeball every diagram.
- Inline SVG: give it a `viewBox`, `max-width:100%`, `role="img"` + `<title>`/`<desc>`, and use `var(--accent)`, `var(--text-muted)`, `var(--border)`, `var(--danger)` etc. as `fill`/`stroke` so it themes with the page.

## 7. Root dashboard is generated, not hand-written

Do **not** hand-edit `/index.html`. After writing a topic's `present/` pages, run:

```bash
node scripts/gen-dashboard.mjs
```

It scans every `<category>/<topic>/present/index.html`, pulls each topic's hero title + tagline, and rewrites `/index.html` so the new topic appears in its category group with the counts updated. The deploy workflow also runs it as a safety net.

## 8. ACCEPTANCE CHECKLIST — self-verify before finishing a topic

Tick every box on **each of the four pages**:

- [ ] Valid standalone HTML: `<!doctype html>`, `<html lang="en">`, `<head>` with `charset`, `viewport`, a page-specific `<title>`, the favicon link, and the `site.css` link.
- [ ] Body has the correct `cat-<category>` class (+ `data-category`).
- [ ] Asset paths are exactly `../../../assets/...` — no absolute or CDN URLs, no web fonts.
- [ ] Full shared shell: skip-link, progress-bar, topbar+hamburger, scrim, sidebar (four nav links, GitHub code link, theme toggle, "← All topics" back button), main/content.
- [ ] Breadcrumb present and correct.
- [ ] Every source-doc section is represented (use §4). Nothing dropped.
- [ ] **All numbers, defaults, dates, and the full trade-off table are preserved** and accurate.
- [ ] Dense paragraphs are broken into bullet lists; words are plain.
- [ ] 3–6 key terms glossed with `.term`; no term glossed twice.
- [ ] ≥1 diagram on every content page **and** the hero diagram on `index.html`. Mermaid renders; inline SVG has `viewBox` + `role="img"` + title/desc and scales.
- [ ] `practice.html` best practices each keep the Do / Why / Avoid triad in a `.practice-card`.
- [ ] **No banned marketing words** (§5).
- [ ] **No horizontal page scroll** at 375px, 768px, 1280px. Wide tables/diagrams/`pre` scroll inside their own box (wrap wide tables in `.table-scroll`). The hero eyebrow tag row wraps.
- [ ] Scripts before `</body>`: mermaid first, then site.js.
- [ ] Page ends cleanly with a `.next-nav`. No stray `{{placeholders}}` or `<!-- IMPLEMENTER -->` comments left.
- [ ] After all four pages: ran `node scripts/gen-dashboard.mjs` so the dashboard lists the topic.
