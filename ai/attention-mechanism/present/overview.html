Overview

◔ ~4 min read ✎ intuition-first

Before attention, models read a sequence one step at a time and squeezed everything they had seen so far into one fixed-size memory. That worked for short sentences and broke on long ones.

ⓘ

In 30 seconds

Attention lets every position in a sequence look directly at every other position and pull in whatever it finds useful, with "useful" learned from data. It is the building block that made transformers — and so GPT, Claude, BERT, and vision transformers — possible.

The mental model

Picture a soft dictionary lookup. A normal Python dict takes a key, finds the one entry that matches exactly, and hands back its value. Attention does the same job, but fuzzy. Each token produces three vectors:

  • A query"here is what I am looking for" — what this token wants to find.
  • A key"here is what I advertise about myself" — what each other token offers.
  • A value"here is what I hand over if you pick me" — the payload that gets passed along.

To build the output for one token, take its query and compare it against every key in the sequence with a dot product. A bigger dot product means a closer match. Those scores turn into weights that add up to 1, and the output is the weighted blend of all the values — a smoothie of every entry, mixed in proportion to how well each one matched the question. Training teaches the model what makes a good query, key, and value for the task at hand.

That is the whole idea. No entry is fetched whole; every entry contributes a little, weighted by fit.

What it is not

⚠

Common mix-ups

  • Not a recurrent network. RNNs pass information step by step through a hidden state; attention compares all positions in parallel.
  • Not a convolution. Convolutions look at a fixed local window; attention's "window" is the whole sequence, and the weights depend on content, not position.
  • Not memory in the database sense. Nothing is stored between passes — queries, keys, and values are recomputed from the current input every time.
  • Not the transformer. Attention is one ingredient; transformers also need feed-forward layers, residual connections, and normalization.

When to reach for it — and when not to

✓ Reach for it when

  • Relationships between distant elements of a sequence matter — language, code, DNA, time series.
  • You want the model to learn what to focus on rather than hard-coding it.
  • You need parallel training on long inputs — attention computes every position in one matrix multiply.
  • You're aligning across modalities, like matching words to image patches.

✕ Skip it when

  • Sequences are very long and the compute budget is tight — plain attention costs grow with the square of length.
  • The problem is strictly local with no long-range structure — a small CNN or MLP is cheaper and sufficient.
  • The dataset is tiny — attention has many parameters and tends to overfit without enough data or regularization.

Key vocabulary

Token
One element of the input sequence — a word piece, an image patch, and so on.
Embedding
The vector representation of a token.
Query (Q)
What a token is looking for.
Key (K)
What each token advertises about itself.
Value (V)
What each token hands over if it's picked.
Attention weights
The normalized similarity scores between one query and all keys.
Self-attention
Q, K, and V all come from the same sequence — every token attends to its peers.
Cross-attention
Q comes from one sequence, K and V from another — e.g. a decoder attending to an encoder.
Transformer
The architecture built around stacked self-attention layers.
