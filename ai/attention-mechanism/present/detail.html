Detail — the deep dive

◑ ~11 min read ✎ What · Where · When · How · Why

What it is

Attention is a differentiable, content-based addressing operation. Given a query matrix Q (shape n_q × d_k), a key matrix K (n_k × d_k), and a value matrix V (n_k × d_v), scaled dot-product attention computes:

Attention(Q, K, V) = softmax( Q K^T / sqrt(d_k) ) V

The output has shape n_q × d_v. Each output row is a weighted blend of the rows of V, where the weights come from how well the matching query row fits every key row. Walked through by shape:

  • Q Kᵀ has shape n_q × n_k — one similarity score per query/key pair.
  • Softmax runs row-wise, turning each row of scores into a probability distribution over the n_k keys. Each row sums to 1.
  • Multiplying that weight matrix by V produces the final n_q × d_v output.

The 1 / √d_k factor is not decoration. If the entries of Q and K are independent with mean 0 and variance 1, the dot product q · k has variance d_k. Without scaling, as d_k grows the values fed into softmax grow too, softmax collapses toward a near one-hot output, and the gradient on every entry but the largest goes to zero — training stalls. Dividing by √d_k keeps the logit variance near 1 no matter the head size, so gradients stay healthy.

The core building blocks

Linear projections W_Q, W_K, W_V
Learned matrices that map input embeddings into query, key, and value subspaces — the only learnable parameters in the attention operation itself.
Score matrix Q Kᵀ
The raw compatibility table between queries and keys.
Softmax normalizer
Converts each row of scores into a probability distribution.
Value aggregator
The second matrix multiply, mixing value vectors by the attention weights.
Mask (optional)
An additive tensor of 0s and −∞s applied before softmax to forbid certain attendances — causal, padding, or document boundaries.
Output projection W_O
For multi-head attention, mixes the concatenated head outputs back into the model dimension.

The original spec is Vaswani et al., Attention Is All You Need (NeurIPS 2017). Attention leads the content-based sequence mixing family. Its siblings are RNNs/LSTMs (state passed step by step), CNNs (fixed local filters), and state-space models like S4/Mamba (a learned but largely input-independent dynamical system). Attention is the only one that recomputes its mixing weights from the data at every layer.

Where it lives

Three architectural placements matter:

Encoder self-attention

Bidirectional, no mask — every token attends to every token. Used by BERT and ViT.

Decoder self-attention

Causal mask — position i cannot attend to positions > i. Used by GPT and Llama.

Cross-attention

Q comes from the decoder, K and V from the encoder output. Used by T5, the original transformer, and vision-language models.

You'll meet attention in LLMs (GPT, Claude, Llama, DeepSeek-V3, Mistral), encoder models (BERT, RoBERTa, ModernBERT), vision (ViT, DINOv2, SAM), speech (Whisper, Conformer), and multimodal systems (CLIP, Gemini and Claude's vision pathways).

Fused kernels

FlashAttention-2/3, xFormers, and PyTorch's scaled_dot_product_attention (auto-dispatched since 2.0+).

KV-cache serving

vLLM (PagedAttention), TensorRT-LLM, SGLang.

Long-context variants

Longformer (sliding window), BigBird (sparse), Linformer (low-rank), Performer (random features), Mamba/Mamba-2 (state-space hybrid).

Position injection

Sinusoidal (original), learned absolute (GPT-2/BERT), RoPE (Llama, Qwen), ALiBi (Bloom, MPT).

When to use it

✓ Reach for it when

  • Token-level interactions carry the task signal — translation, summarization, QA, code, music.
  • You need parallel training across the sequence — attention runs every position through two matrix multiplies; an RNN cannot.
  • The relevant context is content-defined, not position-defined — anaphora, function-call resolution, retrieval.
  • You can afford O(n² · d) time and O(n²) activation memory at your sequence length, or you're willing to use FlashAttention or a sliding-window variant.

✕ Skip it when

  • Sequences run past 100k tokens and the quadratic cost is intolerable — consider sliding-window attention, SSMs (Mamba-2), or hybrid stacks.
  • The task is strictly local (small image patches, fixed-size signals) — a CNN is cheaper and better biased for the job.
  • Training data is tiny — attention layers are over-parameterized and overfit without regularization or pretraining.
  • The latency budget is sub-millisecond on CPU for short inputs — a small GRU can dominate on wall-clock.

A little history

Bahdanau et al. added attention to RNN translation models in 2014 to fix a concrete failure: BLEU scores collapsed on sentences over ~30 words because everything had to compress into one fixed-size context vector. The 2017 transformer dropped the RNN entirely and showed attention alone was enough. By 2018 (BERT, GPT-1) it had taken over NLP; by 2020 (ViT) it took vision; by 2022 (Whisper, AlphaFold) it had spread across modalities.

How it works

For a single self-attention layer with input X (shape n × d_model):

  1. Project. Compute Q = X W_Q, K = X W_K, V = X W_V.
  2. Reshape. Split each into h heads of dimension d_k = d_model / h.
  3. Score. Compute S = Q Kᵀ / √d_k, shape (batch, h, n, n).
  4. Mask (decoder only). Add a strictly upper-triangular −∞ matrix so position i can't see j > i.
  5. Normalize. A = softmax(S) row-wise.
  6. Aggregate. O = A V.
  7. Merge heads. Concatenate along the head axis back to (batch, n, d_model).
  8. Output projection. Y = O W_O.

Minimal pseudocode for the core op, single head, no batch dimension:

def attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / d_k ** 0.5
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    weights = softmax(scores, dim=-1)
    return weights @ V

Multi-head attention runs h of these in parallel on slices of the projected tensors. The point of multiple heads isn't extra capacity — it's specialization: one head might track syntactic dependency, another coreference, another positional offset. GPT-3 uses h=96, d_k=128; Llama-3-8B uses 32 query heads at d_k=128 with only 8 KV heads (GQAgrouped-query attention — several query heads share one key/value head, shrinking the cache).

Attention is permutation-equivariant — shuffle the input rows and the output rows shuffle identically, so word order is lost by default. RoPE (Rotary Position Embedding) puts it back by rotating Q and K so the dot product q_i · k_j becomes a function of i − j — position 2026's default over the original sinusoidal or learned-absolute schemes. ALiBi instead adds a linear penalty −m · |i − j| straight into the scores.

Causal masking is what makes a decoder autoregressive: token i+1 can never peek at itself during training, and the same forward pass yields n parallel next-token predictions. At inference this same masking justifies the KV-cachestored keys and values for past tokens, reused instead of recomputed each step: once a token's K and V are computed they never change, so only the new token's Q runs against the growing cache. Cache size scales as 2 · n_layers · n_kv_heads · d_k · seq_len · batch · dtype_bytes and is usually the dominant memory cost during generation — the reason GQA and MQA (multi-query attention) exist. Llama-2-70B's 8 KV groups for 64 query heads shrink the cache 8×.

Common failure modes

✕

Softmax saturation when scaling is wrong

Forgetting / √d_k, or applying it in the wrong place, collapses gradients on day one of training.

⚠

Attention sink on token 0

In long-context models, the first (BOS) token absorbs a disproportionate share of attention mass — this breaks naive cache-eviction strategies.

✕

OOM on long context

n² activation memory blows past accelerator memory around 8k–32k tokens for naive implementations. FlashAttention is the fix.

⚠

KV-cache memory wall during serving

Long conversations eat tens of GB of cache per request. PagedAttention (vLLM) addresses this.

⚠

Position extrapolation failure

A model trained at 4k tokens with sinusoidal or learned absolute positions degrades sharply past that length. RoPE with NTK-aware scaling or YaRN extends usable length.

✕

Numerical overflow in fp16

Large logits before scaling can overflow fp16. Stable implementations subtract the row max inside softmax first.

✕

Causal-mask leak in custom kernels

An off-by-one in the mask leaks one future token — invisible in loss curves, catastrophic for autoregressive sampling.

Why it exists

Attention solves the information bottleneck in sequence modeling. RNNs had to squeeze a variable-length past into a fixed-size vector and update it one step at a time — lossy, and unfriendly to parallel hardware. Attention removes the bottleneck by letting every output position pull directly from any input position, and removes the serial dependency by computing all positions in two matrix multiplies that map cleanly onto GPU tensor cores. It solved a modeling problem (long-range dependency) and a systems problem (parallel training) at the same time, which is why it took over so fast.

Why it looks the way it does

The non-obvious design choice is content-based weighting via dot products, not learned per-position weights. A per-position weight matrix would need O(n²) parameters, wouldn't generalize across sequence lengths, and wouldn't be permutation-equivariant. Dot products between projected queries and keys give a learned similarity function with zero per-position parameters — the same W_Q, W_K work at any length, on any sequence. Softmax is the smallest differentiable stand-in for "pick the best key" that still lets gradients reach every position. The √d_k scaling is the smallest correction that keeps softmax useful as d_k grows.

The obvious alternative — Bahdanau's additive attention (concatenate q and k, push through a small MLP, output one scalar) — is roughly as good at small d_k but can't be expressed as a single matmul. Dot-product attention won because two big matmuls are the most GPU-friendly primitive there is.

Why it matters now

As of 2026, attention is still the load-bearing primitive in every frontier LLM, every leading vision encoder, and most multimodal systems. The movement isn't away from attention — pure state-space models underperform on associative recall and few-shot tasks — but toward hybrids (Jamba, Zamba, Granite-4) that interleave attention layers with SSM or sliding-window layers, capping quadratic cost while keeping attention's recall behavior. Understanding attention's exact mechanics is the prerequisite for understanding what's shipping now: GQA, Multi-head Latent Attention (DeepSeek-V3), PagedAttention, FlashAttention-3, and the whole long-context optimization literature.
