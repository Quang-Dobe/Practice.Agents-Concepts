Overview

◔ ~3 min read ✎ intuition-first

A neural network cannot read the string "unhappiness". It can only multiply numbers.

ⓘ

In 30 seconds

Tokenization is the fixed, repeatable step that sits between your text and the model. It splits a string into pieces (say ["un", "happiness"]), looks each piece up in a fixed list called the vocabulary the fixed list of every possible token, usually 30k–256k entries, and hands the model a list of integers — one token one entry in the vocabulary; the atomic unit the model sees per integer. Every modern LLM — GPT-4, Llama 3, Gemma, Claude — runs this step before any "thinking" happens. It matters to engineers because tokens are what you get billed for, what fills up the context window, and the root cause of a surprising number of bugs: bad math on numbers, mangled non-English text, odd behavior on emoji.

The mental model

Picture a tokenizer as a phrasebook for a tourist who only knows a fixed list of syllables. You can say anything, but you have to build it from syllables already in the book:

  • Common pieces — " the", " of", "ing" — get their own entry. One lookup, done.
  • Rare words aren't in the book, so the tourist stitches them from smaller pieces: "antidisestablishmentarianism" becomes "anti" + "disestablish" + "ment" + "arian" + "ism".
  • A truly unfamiliar sequence — an obscure emoji, a Cyrillic name — falls back to raw bytes, the most granular page in the book.

The phrasebook is built once, before training, by reading a giant pile of text and asking: which pairs of characters keep showing up together? Promote them to a single entry. That greedy merging is the heart of BPE Byte Pair Encoding — the greedy merge-based algorithm behind GPT-4's tiktoken and Llama 3, the algorithm behind GPT-4's tiktoken and Llama 3. Other algorithms — WordPiece (BERT), Unigram (Gemma, T5) — build the same kind of phrasebook with different statistical recipes, but from the outside they behave almost the same way: frequent stuff is one token, rare stuff is several.

What it is not

⚠

Common mix-ups

  • Not word splitting. "tokenizing" is three tokens in GPT-4, not one.
  • Not embeddings. Tokenization produces integer IDs; embeddings turn those IDs into vectors. A different, later step.
  • Not parsing. The tokenizer has no idea what a noun or a function call is. It is pure string statistics.
  • Not language-specific. Modern tokenizers (SentencePiece, byte-level BPE) work on raw bytes, so they handle Japanese, code, and emoji with the same machinery.

When to reach for it — and when not to

✓ Reach for it when

  • Estimating cost or context usage before sending a prompt to an API.
  • Debugging why a model miscounts characters, fails at arithmetic, or mangles a non-English phrase.
  • Training or fine-tuning a model and choosing — or extending — a vocabulary.
  • Designing a RAG pipeline where chunk size is measured in tokens, not characters.

✕ Skip it when

  • You just need to count words for a UI — use a word splitter, not a tokenizer.
  • You want semantic similarity — that's embeddings, a step downstream of tokenization.
  • You're doing classical string processing (search, regex, diff) — tokens are the wrong unit.

Key vocabulary

Token
One entry in the vocabulary; the atomic unit the model sees.
Vocabulary
The fixed list of all possible tokens, usually 30k–256k entries.
Subword
A token smaller than a word but larger than a character — the sweet spot.
BPE (Byte Pair Encoding)
Greedy merge-based algorithm; the de facto standard.
WordPiece
BERT's variant; merges by likelihood gain instead of raw frequency.
Unigram
Top-down algorithm that starts huge and prunes; used by SentencePiece and Gemma.
SentencePiece
A library, not an algorithm — wraps BPE or Unigram, treats input as raw bytes.
Byte-level
Tokenizer operates on UTF-8 bytes, so nothing is ever truly "unknown".
Special tokens
Reserved IDs like <|endoftext|> or <|im_start|> that carry structural meaning.
