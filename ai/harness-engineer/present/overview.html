Overview

◔ ~3 min read ✎ intuition-first

A language model on its own only turns text into more text. It cannot remember earlier turns, run code, call an API, retry a failed step, or know when to stop.

ⓘ

In 30 seconds

Everything built around the model that makes those things happen is the harness the deterministic software system wrapped around the model: loop, tools, memory, guardrails, tracing. A harness engineer designs and runs that system — the loop that decides what happens next, the tools it can call, the context it sees, the memory it keeps, the checks that gate its outputs, and the traces that record what it did. The shorthand that stuck: Agent = Model + Harness. A decent model with a good harness reliably beats a great model with a weak one.

The mental model

Picture a fighter pilot in a cockpit. The pilot is skilled and fast — but alone, they're just a person in a seat. What makes the aircraft fly is everything built around them: instruments that show what's happening, controls that turn intent into action, an autopilot that handles routine work, alarms that catch mistakes, and a black box that records everything for later review.

The model is the pilot. The harness is the cockpit.

A second analogy carries the same point: an LLM call is a stateless compute unit, like a CPU. The harness is the operating system around it — it schedules work, manages memory, opens files, handles interrupts, and recovers from crashes. Nobody says "the CPU ran the program" — the OS does most of what that sentence means. In a production agent, the model call is a small slice of the system; the harness is the rest.

The loop itself has a name: the agent loop the Thought → Action → Observation cycle the harness runs on every turn. Each turn, the harness decides whether to think, call a tool, or stop. What the model sees on any single call is bounded by the context window the limited text the model can read on one call; the harness decides what goes in, and a guardrail a validator or policy that gates inputs, outputs, or tool calls checks what comes out before it reaches a user or a database.

What it is not

⚠

Common mix-ups

  • Not the model. Swapping one model for another does not rewrite your harness, and a better model does not fix a broken loop.
  • Not prompt engineering. Prompts are one input into a harness; harness engineering owns the whole runtime.
  • Not a framework. LangChain, LlamaIndex, and similar are starter kits. Your harness is the real production system, whether it's built on one of these or not.
  • Not RAG. Retrieval is one component the harness coordinates, not the discipline itself.
  • Not "AI engineering" in general. AI engineering is the umbrella; harness engineering is the runtime-systems specialty inside it.

When to reach for it — and when not to

✓ Reach for it when

  • You're putting an agent in front of real users and "it works on the demo" isn't enough.
  • Your agent has to use tools, call APIs, or change state in the real world.
  • You need traces, retries, timeouts, and budgets — the unglamorous production qualities.
  • You want to swap models without rewriting the application.
  • Multi-step runs are starting to drift, hallucinate tool calls, or silently fail mid-run.

✕ Skip it when

  • It's a single-turn chatbot with no tools and no memory — a prompt is enough.
  • It's a one-off script or a notebook experiment.
  • It's a pure classification or embedding task — no loop, no agency, nothing to wrap.

Key vocabulary

Agent loop / ReAct loop
The Thought → Action → Observation cycle the harness runs.
Tool / function call
A typed capability (search, SQL, shell) the model can invoke.
Context window
The bounded text the model sees on each call; the harness decides what goes in.
Short-term memory
The working scratchpad inside one run.
Long-term memory
A persistent store, often vector-indexed, kept across runs.
Guardrail
A validator or policy that gates inputs, outputs, or tool calls.
Observability / trace
Structured logs of every step the agent took and why.
Stopping condition
The rule that ends the loop: done, budget hit, error, or hand-off.
Control plane
The policy and routing layer that sits above individual agent runs.
