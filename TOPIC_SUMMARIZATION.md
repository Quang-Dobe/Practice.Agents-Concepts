# Web Components

Web Components are the browser's built-in way to define your own HTML tags. Instead of importing a framework component like `<Button />`, you register a plain custom element — `<counter-button>`, `<user-badge>`, `<my-chart>` — and it works in any HTML page, in React, in Vue, in Angular, or in a static site with no framework at all. The browser treats your tag as a first-class citizen alongside `<div>` and `<button>`.

Under the hood, the term "Web Components" is really three separate browser standards that click together. **Custom Elements** let you extend the `HTMLElement` class and register a new tag name; that gives you lifecycle hooks — `connectedCallback` fires when the element enters the page, `disconnectedCallback` when it leaves, `attributeChangedCallback` when attributes change. **Shadow DOM** gives each element its own private subtree of HTML and CSS; a `color: red` rule inside the shadow root never leaks out to the rest of the page, and page-wide styles never leak in. **HTML `<template>`** lets you declare inert markup that the browser parses but doesn't render until you clone it in. Together those three primitives replicate — with no build step and no runtime — most of what a framework component gives you: encapsulation, composition, events, and lifecycle.

Engineers reach for Web Components in three main situations. First, **framework-agnostic design systems**: teams at Adobe, GitHub, Salesforce, Microsoft, and Shopify ship UI libraries as custom elements so React, Angular, and Vue teams can all consume the exact same `<sp-button>` without maintaining three parallel implementations. Second, **embeddable widgets**: chatbots, checkout flows, and comment widgets that get dropped into third-party sites use shadow DOM to bulletproof themselves against the host page's CSS — no more accidental `* { box-sizing: border-box }` breaking your widget. Third, **long-lived UI**: a plain custom element still works ten years from now, because it's part of the browser platform, not a framework version. What you don't reach for them for is greenfield SPAs already fully committed to React, or SEO-critical server-rendered pages before Declarative Shadow DOM was widely supported.

The mental model to hold: a Web Component is `class MyThing extends HTMLElement`, registered with `customElements.define('my-thing', MyThing)`. In its constructor it opens a shadow root and stamps in some HTML and CSS. It watches a few attributes, dispatches typed CustomEvents when things happen, and exposes properties for imperative use. That's the whole primitive. Frameworks like Lit, Stencil, and FAST are just ergonomic sugar around that same three-standard foundation — the standard itself is what browsers ship and what will still be running when today's frameworks are historical footnotes.
