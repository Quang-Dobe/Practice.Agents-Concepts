Overview

◔ ~4 min read ✎ intuition-first

Before Grid, page layout was built out of tools meant for other jobs: floats (made for wrapping text around images) and tables (made for tabular data). Both worked. Both were miserable.

ⓘ

In 30 seconds

Grid has shipped in every browser since 2017. A container declares an actual grid of tracks rows and columns — one track is one row or one column — grid-template-columns: 200px 1fr 200px — and each child claims a rectangle inside it. The layout maths (leftover space, gaps, stretching) is the browser's problem, not yours. If you have ever fought a three-column dashboard with a sticky sidebar, this is the tool that ends the fight.

The mental model

Think of laying out a floor of an office building.

  • Flexbox is seating people on a bus. One aisle, one direction. You hand the driver a rule — "spread everyone out evenly", "push the last two to the back" — and passengers arrange themselves along that single line. Simple, and it adapts well when someone gets off. But if you want the person in seat 3 to line up with someone in a different row, you are out of luck: rows do not know about each other.
  • Grid is the architect's floor plan. You draw the walls before anyone moves in: three columns, four rows, a 16px corridor between everything. Then you assign tenants: "Accounting takes the whole top strip. Engineering takes columns 1 through 2, rows 2 through 4." Tenants can span several cells, sit on top of each other, or be dropped in unassigned and let the building manager find them a free room — that is auto-placement the algorithm that finds a slot for items you did not position yourself.

Two consequences of "the parent draws the plan"

  • A child's position is decided by the layout, not by its own size. A <div> can start at column 2 and stretch to column 4 without knowing what is inside it.
  • Source order and visual order can differ. You can put the sidebar last in HTML and first on screen. Useful, and a real accessibility trap — keyboard and screen-reader order still follows the HTML.

The killer unit: fr

One fr is one fraction of the leftover space. fr a share of the free space left after fixed tracks and gaps are subtracted means grid-template-columns: 200px 1fr reads as "200 pixels for the nav, and whatever remains for the content" — no calc(), no percentages that break the moment you add a gap.

What it is not

⚠

Common mix-ups

  • Not a replacement for Flexbox. Flexbox is one-dimensional — a row of buttons, a toolbar. The two are used together, constantly.
  • Not display: table. Tables size themselves from their content; a grid's tracks are declared up front.
  • Not a CSS framework. Bootstrap's "grid" is a 12-column convention built from classes; CSS Grid is a browser primitive with no classes at all.
  • Not a component system. It positions boxes. It says nothing about state, styling, or reuse.

When to reach for it — and when not to

✓ Reach for it when

  • You need page-level scaffolding: header / sidebar / main / footer.
  • Things must align across both rows and columns — dashboards, pricing tables, card galleries.
  • You want responsive layout without media queries, via repeat(auto-fit, minmax(240px, 1fr)).
  • Elements must overlap — a caption sitting on top of an image — without position: absolute.
  • Nested cards' internal rows must line up with their siblings. That is what subgrid is for.

✕ Skip it when

  • It is a single row or column with no cross-axis alignment needs — Flexbox is less code.
  • The content is real tabular data — use a <table>; semantics matter more than layout convenience.
  • Content flows and items size themselves, and you genuinely do not care about column alignment.

Key vocabulary

Grid container
The element with display: grid; it owns the plan.
Grid item
A direct child of that container. Grandchildren are not items.
Track
One row or one column.
Grid line
The numbered dividers between tracks; placement is expressed in lines, not tracks.
Cell / area
One square; an area is any rectangle of cells.
fr
A share of the free space remaining after fixed sizes and gaps.
Explicit vs implicit grid
Tracks you declared, versus tracks the browser invented because items overflowed.
Auto-placement
The algorithm that finds a slot for items you did not position.
minmax() / repeat()
Track-sizing helpers; minmax(200px, 1fr) is the responsive workhorse.
subgrid
A nested grid that inherits its parent's tracks instead of defining its own. Baseline in all major browsers since 2023.
◆

One thing still in motion

Native masonry — Pinterest-style staggered columns — is being standardised in Grid Level 3 and has shipped in Safari, but is flagged or absent elsewhere as of mid-2026. Treat it as progressive enhancement behind @supports.
