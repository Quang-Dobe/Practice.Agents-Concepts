Overview

◔ ~3 min read ✎ intuition-first

You can invent your own HTML tag. Give it a private DOM tree and private CSS, wire up behavior in a small JavaScript class, and register it once with the browser. From then on it works everywhere HTML works.

ⓘ

In 30 seconds

A Web Component is a custom tag — say <user-card> — that ships with its own Shadow DOM a private DOM subtree; outside CSS and JS queries can't see or touch what's inside it. You define it once in JavaScript and it runs in React, Angular, Vue, a plain .html file, or a Rails view — no bundler, no rewrite per framework.

The mental model

Picture a sealed appliance, like a microwave. From the outside it has a clean interface: a few buttons, a power cord, a door where you put your food. Inside, it has its own wiring and its own casing — the kitchen's electrics can't reach in and rearrange the magnetron, and your page's global CSS can't bleed in and repaint the microwave's display.

  • The buttons are attributes — you configure the component from markup.
  • The cord is events — the component talks back out to the page.
  • The door is a slot a placeholder in the private tree where the tag's own children get displayed — the plain HTML you put between the tags still shows up, just projected into a spot the component chose.
  • The sealed casing is Shadow DOM — the private tree that outside styles and queries cannot cross.

The children you write between the opening and closing tag — <hello-badge>Quang</hello-badge> — stay visible to the outside page as the light DOM the element's own children, written by whoever uses the tag; they live outside the shadow tree. The Custom Element a class extending HTMLElement, registered under a hyphenated tag name class decides what happens once that tag lands in the page. Put a shadow root, a template, and a custom-element class together and you get a component with the isolation a framework component wishes it had — shipped by the browser, no bundler required.

What it is not

⚠

Common mix-ups

  • Not a framework. React, Vue, and Svelte give you rendering, state, and routing. Web Components give you one primitive: a custom tag with isolation.
  • Not iframes. An iframe is a separate document with its own URL and network context. A Web Component shares the page's JS runtime — it's just scoped DOM.
  • Not React components. A React component is a compile-time abstraction the browser never sees. A Web Component is a real DOM node the browser understands natively.
  • Not WebAssembly. WASM runs sandboxed binary code. A Web Component is plain JavaScript that produces DOM.

When to reach for it — and when not to

✓ Reach for it when

  • You're building a design system that has to work across React, Angular, and legacy jQuery pages.
  • You ship an embeddable widget — a chat bubble, a checkout button — that must survive an unknown host site's CSS.
  • Different teams pick different frameworks in a micro-frontend setup but need to share one tag.
  • You want one interactive island on an otherwise static page, without pulling in a framework.

✕ Skip it when

  • You're already all-in on one framework and never plan to leave — its own component model has better tooling and server-rendering support.
  • You need heavy SSR with fine-grained streaming — the ecosystem here is still thinner than Next.js or SvelteKit.
  • The component is trivial and used only once. A plain function or partial is lighter.

Key vocabulary

Custom Element
A class extending HTMLElement, registered under a hyphenated tag name.
Shadow DOM
An encapsulated DOM subtree attached to an element; styles and queries do not cross the boundary.
HTML Template
A <template> tag whose contents are parsed but inert until cloned.
Slot
A placeholder inside the shadow tree where the host's light-DOM children get projected.
Light DOM
The children written between the opening and closing custom tag, visible to the outside page.
Lifecycle callbacks
connectedCallback, disconnectedCallback, attributeChangedCallback, adoptedCallback.
customElements.define
The browser API that ties a tag name to a class.
Declarative Shadow DOM
Server-rendered shadow trees via a template with shadowrootmode="open" — no JS needed for first paint.
