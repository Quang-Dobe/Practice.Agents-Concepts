Overview

◔ ~3 min read ✎ intuition-first

Lots of features care whether something is on screen: lazy images, infinite scroll, "mark as read", ad impressions, scroll-in animations. The old way measured every element on every scroll event. IntersectionObserver lets the browser do that work for you.

ⓘ

In 30 seconds

  • The old way: listen to scroll and call getBoundingClientRect() on each element. That runs on the main thread dozens of times per second and forces layout the browser's step that works out every element's size and position work.
  • The IO way: you list the elements you care about. The browser calls you back only when their visibility crosses a line you picked.
  • Why it's cheaper: the browser already computes layout and clipping while it renders, so it does the geometry for you.

The mental model

Picture a security guard watching a wall of CCTV monitors.

  • The monitor frame is the root the box that counts as "visible"; usually the browser viewport.
  • The people walking past are your targets the elements being watched, added with observe(el).
  • Scroll listener: you phone the guard every 16 ms: "Is Alice on camera? What about Bob?" Most answers haven't changed, and every call interrupts the guard.
  • IntersectionObserver: you hand the guard a list and a rule: "Radio me when Alice is at least half on screen, and again when she leaves." You stop asking. The guard reports only when someone crosses your line, and saves up several reports to hand over together.

The two knobs

  • Threshold — how much of the target must show before the guard reports.
    • 0 = any pixel showing.
    • 1 = fully in frame.
    • [0, 0.5, 1] = report at each of those points.
  • Root margin — stretch or shrink the monitor frame before checking. rootMargin: "200px" means "tell me when Alice is within 200px of coming on camera". That is how lazy-loaders start fetching an image before you see it.
const io = new IntersectionObserver((entries) => {
  for (const e of entries) {
    if (e.isIntersecting) loadImage(e.target);
  }
}, { rootMargin: "200px", threshold: 0 });

document.querySelectorAll("img[data-src]").forEach((img) => io.observe(img));

This is a simplification. The callback runs asynchronously later, in its own task, not at the exact moment a pixel crosses the line. The Detail page covers the timing you do get.

What it is not

⚠

Common mix-ups

  • Not ResizeObserver. That reports when an element's size changes, not whether it is visible.
  • Not MutationObserver. That reports DOM changes — added nodes, changed attributes.
  • Not proof a human saw it. An element can "intersect" while hidden behind another element or at opacity: 0. The experimental v2 option trackVisibility tries to close that gap; browser support varies.
  • Not a scroll-position API. It reports threshold crossings, not a steady stream of scroll offsets. For effects tied to scroll position, use CSS scroll-driven animations.

When to reach for it — and when not to

✓ Reach for it when

  • Lazy-loading images, iframes, or heavy components as they get close to the viewport.
  • Infinite scroll: watch a sentinel <div> at the bottom of the list and fetch the next page when it shows.
  • Analytics and ad viewability: "was this card at least 50% visible?"
  • Starting and pausing videos or animations based on whether they are on screen.
  • Highlighting the active section in a table of contents as the reader scrolls.

✕ Skip it when

  • You need pixel-accurate, per-frame scroll effects like parallax. Batched, async callbacks look janky.
  • Native loading="lazy" on <img> or <iframe> already does the job.
  • You check visibility once. A single getBoundingClientRect() is simpler.
  • You must prove an element was not covered or tampered with — unless you accept v2's limited browser support.

Key vocabulary

Target
The element being watched, registered with observe(el).
Root
The box used as the visible area. null means the viewport; otherwise it must be an ancestor of the target.
Threshold
One or more ratios from 0 to 1 that trigger a callback when crossed.
rootMargin
A CSS-margin-style string that grows or shrinks the root box before intersection is tested.
IntersectionObserverEntry
The object your callback gets for each change, with isIntersecting, intersectionRatio, boundingClientRect, and time.
intersectionRatio
The fraction of the target currently visible inside the root, from 0 to 1.
unobserve / disconnect
Stop watching one target, or stop watching all of them.
