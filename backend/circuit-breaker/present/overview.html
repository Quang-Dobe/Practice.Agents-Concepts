Overview

◔ ~3 min read ✎ intuition-first

Services call other services. When a callee gets slow or starts failing, the naive move is to keep calling it — and that is exactly how one outage spreads to everything.

ⓘ

In 30 seconds

A circuit breaker sits in front of an outbound call and watches the failure rate. Once things look bad it stops calling for a while — callers get an instant error or a fallback a cheaper backup answer: a cached value, a default, or a friendly error instead of waiting on a doomed request. After a cool-down it cautiously tests whether the other side is healthy again before resuming normal traffic.

The mental model

Think of the breaker in your home electrical panel. Under normal load, current flows through it and you never think about it. If something downstream shorts out, the breaker trips — it physically opens the circuit so the fault can't burn the wiring upstream. You wait, fix the appliance, and flip it back on. A software breaker does the same job for a network call.

Picture OrderService calling PaymentService. Payments is having a bad day: its database is locked and responses take 30 seconds before timing out. Every request from Orders eats a thread, a connection, and some memory for 30 seconds. Orders runs out of threads. Then the service calling Orders runs out of threads. Within minutes a payments problem is a checkout outage, then a homepage outage. That spread is cascading failure one service's outage propagating upstream through synchronous calls — the single biggest reason small incidents become company-wide ones.

The breaker stops that. Once it sees, say, 50% of recent calls fail, it opens: every later call returns immediately, so no thread is held and no 30-second wait happens. The failing service gets breathing room to recover instead of being hammered by retries.

Two words carry the recovery story. When the breaker is Open it lets callers fail fast return an error immediately instead of waiting for a doomed call. After a timeout it moves to half-open a probe state that admits a few real calls to test recovery: if those trial calls succeed it closes and traffic resumes; if they fail it snaps back open.

The three states in one line each

  • Closed — normal operation; calls pass through and failures are counted.
  • Open — calls fail instantly without touching the network.
  • Half-Open — a probe lets a few real calls through to test recovery.

What it is not

⚠

Common mix-ups

  • Not a retry. A retry assumes the failure is transient and tries again now; a breaker assumes it is sustained and refuses to try at all. They compose: retry inside, breaker outside.
  • Not a rate limiter. Rate limiters cap traffic you choose to send. Breakers react to traffic that's already broken.
  • Not a timeout. A timeout bounds a single call. A breaker uses timeouts as one signal among many to decide whether to keep calling.
  • Not a load balancer. A breaker decides whether traffic goes, not where it goes.

When to reach for it — and when not to

✓ Reach for it when

  • A synchronous call to another service can stall your own threads.
  • You call a flaky third-party API — payment gateway, SMS provider, geocoder.
  • "Fail fast with a fallback" is better UX than "spin for 30 seconds and then fail".
  • You run high-fan-in services where one slow dependency can drain the whole worker pool.

✕ Skip it when

  • The call is pure in-process — there's nothing to break.
  • The work is async and queue-based — backoff and dead-letter queues fit better.
  • Every request must eventually succeed and there is no acceptable fallback.
  • The system is tiny, with one downstream and no real cascade risk. The complexity isn't free.

Key vocabulary

Cascading failure
One service's outage propagating upstream through synchronous calls.
Closed / Open / Half-Open
The three breaker states.
Failure threshold
The error rate or count that trips the breaker.
Cool-down
How long the breaker stays open before probing (the reset timeout).
Fallback
The alternative response returned when the breaker is open.
Fail fast
Return an error immediately instead of waiting for a doomed call.
Bulkhead
Sibling pattern that isolates resource pools so one bad dependency can't drain all your threads.
Probe
The half-open trial request used to test recovery.
